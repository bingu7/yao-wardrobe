# FR-001 新增衣物 — 实施计划（PLAN）

> 契约化规格：功能已在代码库中实现。本计划按「从零实现 FR-001」的步骤组织，映射到现有代码结构，作为实现参考、维护指引与后续单元测试的依据。各步骤的「如何做」见 `spec.md`。

## 前置条件

- 微信小程序原生项目，无 npm 依赖、无构建链（`project.config.json` libVersion 3.8.0）
- 数据层基础（`utils/wardrobe.js` 存储键、规范化、图片工具）就绪
- 运行/验证环境：Node.js（执行测试）、微信开发者工具（人工验证页面交互）

## Phase 1 — 数据层：衣物写入与规范化

**1. 数据模型与存储** - 在 `utils/wardrobe.js` 定义衣物存储键与读写接口：读取时缓存非数组回退空数组，保存走统一写入口，为后续所有衣物功能提供稳定基础。参考 spec §3、§4.1。

**2. 新增记录写入** - 实现 `upsertItem` 的新增路径：生成唯一 ID、自动维护创建/更新时间戳、保存前规范化字段（季节/场合数组、穿着计数、最近穿着日期）、插入列表首项并返回 ID。参考 spec §4.1、§3.1。

**3. 规范化与读取** - 实现 `normalizeItem` 与 `getItem`，保证新增记录被任何读取方（列表、详情、统计）使用时字段类型稳定；不存在的 ID 返回空。参考 spec §3.2、§4.2。

**4. 表单选项来源** - 接入分类与场合选项接口（含自定义项与默认值合并），使表单页可枚举可选分类、场合、季节、状态。参考 spec §4.2。

## Phase 2 — 添加页：表单、校验与交互

**5. 表单骨架与字段绑定** - 在 `pages/add/add` 搭建表单页：图片上传区、名称/价格/颜色输入、季节与场合多选 chips、购买日期、状态、备注，以及保存按钮栈（保存 / 保存并继续添加）。参考 spec §5.1。

**6. 页面层校验** - 实现名称、分类、价格的校验规则与内联错误展示：名称与分类必填，价格为空或非负且最多两位小数；任一失败阻止保存并给出提示。参考 spec §4.3、§6。

**7. 选择面板交互** - 实现分类、场合、状态、日期四个面板：分类面板支持选择与编辑（新增/重命名/排序/删除），场合面板支持多选与自定义，状态面板单选，日期面板含快捷日期与日期选择器；面板操作与表单状态保持同步。参考 spec §5.2。

**8. 保存流程与防重** - 实现保存动作：校验通过后构造规范化数据写入存储，成功反馈、复位表单与加载态；「保存并继续添加」留在表单页连录，普通保存返回衣橱首页。参考 spec §4.3、§5.3。

## Phase 3 — 图片生命周期与编辑复用

**9. 图片选择与持久化** - 接入媒体选择与持久化保存：相册/相机选图后转为持久文件路径写入表单，处理选图失败、移除图片与连续选图时对未使用临时图的清理，页面离开时回收未保存图片。参考 spec §3.4、§4.2。

**10. 编辑模式加载** - 支持从详情页进入编辑：读取并消费临时交接键，回填全部字段与选择状态，记录原图路径，标题切换为编辑语义。参考 spec §5.4。

**11. 编辑保存与旧图清理** - 编辑保存复用新增路径；原图被替换或移除时，对不再被引用的旧图片发起清理，避免存储堆积。参考 spec §3.4、§4.3。

## Phase 4 — 入口接入与数据闭环

**12. 首页入口与跳转衔接** - 在衣橱首页接入「＋ 添加」入口与保存后的返回衔接，确认 Tab 切换、页面注册与标题配置完整，新增→列表可见的数据闭环打通。参考 spec §2、§4.4。
