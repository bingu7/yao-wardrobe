# 瑶的衣橱（yao-wardrobe）产品需求文档（PRD）

> 版本：v1.0 ｜ 日期：2026-08-08 ｜ 依据：当前代码库（README.md / docs/API.md / pages/ / utils/wardrobe.js / tests/）
> 本文档全部功能均来源于真实代码，未虚构功能。

## 1. 项目概述

### 1.1 产品定位
一款「个人衣橱管理」类原生微信小程序，帮助用户在手机本机管理衣物、记录每日穿着、组合穿搭、维护购买愿望并统计穿着成本。

### 1.2 架构边界
- 纯前端小程序，**无服务器、无云函数、无账号体系、无 HTTP 请求**。
- 所有业务数据存储于微信本地缓存（`wx.setStorageSync`），图片存于小程序持久文件目录（`wx.env.USER_DATA_PATH`）。
- 备份与恢复由用户手动操作（复制/分享/导入 JSON 文件），不做云端同步。
- 技术栈：原生小程序（JS + WXML + WXSS），无 npm 依赖；核心业务集中在 `utils/wardrobe.js`（导出 5 个常量 + 65 个函数）。

### 1.3 目标用户
个人用户（无多人/多设备使用诉求），核心诉求为「管理自己有多少衣服、花了多少钱、每天穿什么、什么闲置了」。

### 1.4 核心价值
- 零成本本机管理：数据不出设备，隐私安全；
- 穿着记录驱动统计：穿了多少次、单次成本、闲置提醒、本周推荐；
- 穿搭组合 + 穿搭计划：把衣物变成可执行的每日穿搭安排。

## 4. 关键业务流程

### 4.1 添加衣物
衣橱首页「＋ 添加」→ 添加页填写表单（选图→`wx.chooseMedia`→`persistImage` 转持久文件；选分类/季节/场合；价格校验）→ 保存 → `upsertItem` 写入本地缓存 → 返回衣橱首页；可选「继续添加」连录。

### 4.2 记录穿着
衣橱首页「今日穿搭日历」→ 穿着日历页 → 默认今天（picker 限制 end=今天，最近 21 天快速回看）→ 勾选当天穿过的衣物 → 保存 → `setWearLog` 覆盖当日记录并自动重算所有衣物的 wearCount / lastWornDate / updatedAt。同天重复记录不重复计数。

### 4.3 穿搭计划 → 实际穿着
穿搭 Tab → 穿搭计划 → 月历选日期 → 选择穿搭 + 备注 → 保存计划（`setOutfitPlan`）→ 到计划当天点击「记录穿着」→ `markOutfitPlanWorn` 将该穿搭内仍有效的衣物并入当日穿着日志，已记录的衣物跳过。

### 4.4 愿望转入衣橱
愿望 Tab → 「转入衣橱」确认 → `purchaseWishlistItem`：用愿望字段（名称/分类/图片/预计价格/备注）创建衣物（status=偶尔穿，purchaseDate=今天）→ 从愿望清单移除。

### 4.5 备份与恢复
设置页 → 生成完整备份（v4，图片转 Base64）→ 复制/分享文件/保存到电脑 → 换机或清数据后：粘贴备份或选择 JSON 文件 → `validateBackup` 校验 → 确认合并数量 → `importDataWithImages` 把图片写入本地目录、按 ID+updatedAt 合并数据、重算穿着统计。

### 4.6 换季整理
统计页查看季节分布 → 衣橱首页按分类筛选 → 批量模式改分类/追加场合/删除 → 结合「久未穿着」与「本周推荐」决定继续穿或闲置/删除。

## 5. 数据模型

### 5.1 主要实体

**衣物 WardrobeItem**（存储键 `privateWardrobeItems`）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 唯一 ID（`item_时间戳_随机串`） |
| imageUrl | string | 持久图片路径（可能为空） |
| name / category | string | 名称、分类（分类可自定义，含兜底「其他」） |
| price | number\|'' | 价格，空串表示未填写 |
| color | string | 颜色 |
| seasons | string[] | 可选春/夏/秋/冬 |
| occasions | string[] | 自定义场合集合 |
| purchaseDate | string | YYYY-MM-DD |
| status | string | 常穿/偶尔穿/闲置 |
| wearCount / lastWornDate | number / string | 穿着次数与最近穿着日期（由日志自动维护） |
| note / createdAt / updatedAt | string | 备注、创建与更新时间（ISO 8601） |

**穿搭 Outfit**（`privateWardrobeOutfits`）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id / name / occasion / note | string | 基础字段 |
| pieces | Array<{category, itemId}> | 部件列表（≤5，读取时去重并剔除失效衣物） |

**穿搭计划 OutfitPlan**（`privateWardrobeOutfitPlans`，键为日期）
`{ outfitId, note, createdAt, updatedAt }`，与实际穿着记录相互独立。

**愿望 WishlistItem**（`privateWardrobeWishlist`）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id / imageUrl / name / category | string | 基础字段 |
| expectedPrice | number\|'' | 预计价格 |
| matchItemId | string | 关联的衣物 ID（衣物被删时清空） |
| note / createdAt / updatedAt | string | 备注与时间戳 |

**穿着日志 WearLogs**（`privateWardrobeWearLogs`）
`Record<YYYY-MM-DD, string[]>`，值为当天穿过的衣物 ID。

**备份 BackupData**
`{ version: 3|4, exportedAt, items, outfits, wishlist, wearLogs, outfitPlans?, categories, occasions, images? }`；v4 的 `images` 为 `{ imageRef: { extension, data(base64) } }`。

### 5.2 枚举/默认值
- 默认分类：连衣裙、上衣、下装、外套、鞋子、包包、帽子/发饰、配饰、其他
- 季节：春、夏、秋、冬；状态：常穿、偶尔穿、闲置
- 默认场合：通勤、约会、旅行、拍照、正式、休闲、运动
- 闲置提醒阈值：60 天；统计「90 天未穿」使用独立口径（>90 天）

### 5.3 页面间临时状态
`wardrobeEditingId`、`outfitEditingId`、`outfitCopyData`、`wishlistEditingId` 通过本地缓存交接，目标页读取后立即删除。

## 6. 非功能需求

### 6.1 性能
- 搜索使用 300ms 防抖，避免频繁全量过滤；
- 数据全部走 `wx.setStorageSync` 同步读写，页面级不引入额外网络；
- 备份/恢复/批量存图等耗时操作用 `wx.showLoading` 遮罩，避免重复操作。

### 6.2 可靠性
- 级联一致性：删除衣物自动清理穿搭引用、愿望关联、穿着日志与无用图片（`removeImageFileIfUnused`）；
- 幂等性：同日重复记录穿着、重复执行计划写入、重复导入同一备份均不会重复计数；
- 图片生命周期：编辑替换、加载失败、删除时均清理不再被引用的本地文件，防止存储堆积；
- 已知缺陷（tests/TEST_REPORT.md 确认，尚未修复）：见第 7 节。

### 6.3 兼容性
- 基础库版本要求：libVersion 3.8.0；
- 运行时能力探测：`typeof wx.xxx === 'function'` 判断（文件分享、保存到磁盘、分享图片菜单等），不支持的平台降级提示；
- 平台适配：开发者工具/Windows/Mac 桌面端与手机端分别处理备份导出与分享。

### 6.4 隐私与合规
- 不上传任何数据到服务器，数据仅存本机；
- 隐私政策、用户协议内置；相册/剪贴板权限在使用时由用户主动触发；
- 正式发布需补齐备案号。

### 6.5 可维护性 / 可测试性
- 业务逻辑集中在 `utils/wardrobe.js` 单一模块（70 个导出成员），页面只做视图与事件；
- 使用 Node 内置 assert 编写测试，无 npm 依赖，可直接 `node tests/wardrobe.test.js` 运行；
- 已存在回归测试（138 用例）、迁移测试（7 组）与 E2E 场景测试（4 场景 135 断言）。

## 7. 待明确的问题

1. **已知未修复缺陷**：`getOutfits()` 旧格式迁移结果未写回存储（B1）；存储损坏（含 null 元素）时 `getOutfits()` 崩溃（B2，崩溃级）；`getCostPerWear/getIdleStatus/enrichItemForDisplay` 对 null 入参抛异常、`addWishlistItem(null)` 会静默创建空记录（B3-B5）。是否纳入近期修复计划？
2. **跨设备数据**：当前无账号体系与自动同步，换机/清缓存/卸载即丢数据，仅靠手动备份合并。是否规划云同步？
3. **合并冲突语义**：备份合并按 ID + updatedAt 判定新旧，ID 由本地时间戳+随机串生成，不保证跨设备唯一，导入可能产生覆盖或分叉。是否引入 UUID 或冲突提示？
4. **剪贴板容量**：v4 完整备份含 Base64 图片，图片较多时内容可能超出剪贴板/传输限制，是否需要分块或提示改选文件导出？
5. **API 不一致**：`addWishlistItem` 不返回 id（页面实际使用 `upsertWishlistItem`）；`buildCategoryPanelItems` 的 `customCategories` 参数当前未被使用。是否有意保留？
6. **写入一致性**：涉及多存储键的级联写操作非事务，中途失败无回滚（如导入中断可能留下部分数据）。是否需要幂等重试或事务化？
7. **占位信息**：设置页备案号为占位文本；`IDEA.md` 仅一句话（"一个衣橱微信小程序"），产品愿景与路线图缺失，是否补充？
